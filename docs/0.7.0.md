# 0.7.0: 태스크별 결정 브리핑과 참조 구분

`vibe brief`(단독)와 `work brief`(작업 묶음·실행기·`vibe loop`)가 같은 조립기(`src/spec-context.mjs`)를 쓴다. 목표는 작업마다 읽는 양을 줄이되 정책·조건·예외를 빠뜨리지 않는 것이고, 크기만으로 성공을 판정하지 않았다. 이 작업에서 npm 게시·원격 push는 하지 않았다.

## 참조 문법 (FORMAT Notation)

`→!AUTH-3` 필수 의존 · `→=AUTH-3` 정본 위임 · `→~AUTH-3` 관련 설명 · `→AUTH-3` 미분류. 표시 하나가 `/` 목록·`–` 범위(`→!AUTH-3/5`, `→AUTH-3–6`, `..`도 허용)에 적용되고, `→AUTH`는 도메인 전체, 화살표 없는 `AUTH-3`은 미분류로 센다. 코드 span 안은 읽지 않고, 존재하지 않는 도메인 이름(`UTF-8`, `SHA-256`)은 참조가 아니다. 실제 프로젝트에서 화살표 참조 957개, 맨 ID 11개, 도메인 참조 8개를 읽었고 깨진 대상은 없었다.

- 기존 `→`는 미분류 그대로다. 선택 참조로 바꾸지 않고, 추측으로 일괄 분류하지 않는다. create-ssot·update-ssot는 새로 쓰는 참조에 종류를 붙이고, doc-review는 문장이 종류를 분명히 말할 때만 붙인다(`→!`·`→=`를 `→~`로 내리는 것은 update-ssot 거리).
- lint: 깨진 typed 참조 = 오류, 깨진 미분류 참조·정본 위임 순환·`[o]`가 아닌 정본 대상 = 경고, 미분류 참조 수 = 검토 후보 1건, cfg `always`·`brief` 값 검증. FORMAT에 정의가 없는데 typed 표시가 쓰이면 경고.

## 호환

- `context`는 바뀌지 않았다. `work brief --attempt <id>` 호출과 기존 필드(`attempt`, `group`, `commit`, `taskId`, `tasks[].{id,current,file,content}`, `decisions[].{id,text}`, `verify`, `correction`, `directive`)는 그대로이고 필드가 추가됐다. `decisions`는 인용 결정이 앞에 같은 순서로 오고 그 뒤에 의존·전역 결정이 붙는다(각 항목에 `via`·출처).
- 0.6.0의 `vibe brief T###`(미게시)는 `taskId`·`diffBase`·`freshness`·`verify`·`touches`를 유지하고, 기본 출력이 마크다운이 됐다(`--json`으로 JSON). `task`에서 `content`는 빠지고 `tasks[0].content`에 있다.
- 설치: `.claude/skills`·`.codex/skills`에 같은 파일, 로컬 수정은 충돌로 보고(덮어쓰지 않음), `spec/`은 건드리지 않는다. 임시 프로젝트에서 설치 62개 생성 → 재설치 62개 동일 → `check` 정상 → 로컬 수정 파일 충돌 보고를 확인했다.
- 실제 프로젝트 lint: 오류·경고 수 변화 없음, 검토 후보 +1(미분류 참조 집계).

## 정책 질문 대조

브리핑을 보지 않은 에이전트 3개가 태스크(T201·T209·T225)와 SSOT 전체를 읽고 예외·금지·수치·조건 위주의 질문 25개와 근거 인용 47개(원문과 글자 단위 일치를 확인)를 만들었다. 질문은 근거 인용이 브리핑에 모두 그대로 있을 때만 "답할 수 있음"으로 셌다.

- `cited`가 놓친 근거(T209: MATCH-1·2·7·18, PLAYER-3 / T225: MATCH-5·7·14·19·20, WEB-17·22)는 모두 인용 도메인 안에 있지만 태스크가 인용하지도, 인용 결정이 참조하지도 않는 결정이다. 참조 분류로는 메워지지 않고 인용이 완전해야 한다 — create-task가 "구현이 지켜야 하는 결정을 빠짐없이 인용"하도록 바뀐 이유다.
- 역참조는 T201의 CLUB-3·CLUB-16(인용 결정 PLAYER-1·15·17을 가리키는 다른 도메인 결정)을 찾았다(6→8).
- always:-는 T209의 ARCH-5(`Math.random` 금지)를 놓쳤다 — 전역 규칙을 줄일 때 이런 결정을 남겨야 한다.
- 합성 fixture에서는 같은 방식의 질문 6개를 테스트로 고정했다(`test/spec-context.test.mjs`): 새 브리핑은 6개 모두, 인용 블록만으로는 1개 근거만 담는다.

결론: 이 프로젝트의 기존 태스크에서는 안전한 기본값(`domain`)이 0.5 정독과 비슷한 크기(중앙값 110k 대 103k — chg·STATE·FORMAT은 빠지고 의존·역참조·다른 도메인 섹션이 더해짐)이고, 크기 감축(중앙값 48k, always 축소 시 25k)은 `cited`와 완전한 인용에서 나온다. 인용이 불완전한 상태에서 `cited`로 바꾸면 정책이 빠진다.

## 검증

- `npm run check`: 전체 테스트 + validate + pack:check (결과는 최종 보고에).
- 새 테스트 `test/spec-context.test.mjs` 20개: 직접 인용·다단계 필수 의존, 관련 제외·정본 포함, 순환·중복·없는 참조, `/`·`–`·도메인·맨 ID 참조, 조건·예외·수치·단위·부정·의무 보존(정책 질문 6개), 표·하위 항목·빈 줄 보존, flow·constraints, 현재 규칙과 rev 범위 이력·chg 공백, `[?]`·`[x]`, 작업 트리 대 고정 커밋(미커밋 변경), 결정적 순서·출처, 형식 오류 줄, CLI 마크다운·`end` 줄·종료 코드, 단일 태스크 필드 호환, 범위 기본값·역참조·잘못된 범위. lint 테스트 2개 추가, `work brief`·`vibe brief` 기존 테스트는 새 필드에 맞춰 갱신.

## 남은 제약

- 기본값은 기존 태스크의 인용이 불완전하다는 전제의 보수적 선택이라 크기 이득이 작다. 프로젝트 단위 `brief: cited` 전환만 있고 태스크 단위 전환은 없다 — 새 규칙으로 만든 태스크와 기존 태스크가 섞인 프로젝트는 기존 태스크가 소진될 때까지 `domain`이 맞다.
- 정책 질문은 3태스크 25개 표본이고, 근거 문자열이 들어 있는지만 본다. 모델이 그 근거로 실제로 올바르게 답하는지는 측정하지 않았다.
- 미분류 참조는 인용·필수 블록에서 1단계만 따라간다. 도메인·전역·역참조·1단계로 들어온 블록의 미분류 참조는 `unfollowed`로만 남는다(`--deep`으로 끝까지).
- 역참조는 인용 결정만 대상으로 하고, 다른 도메인의 flow·constraints 안 참조는 역참조로 싣지 않는다.
- FORMAT은 install로 이관되지 않는다. README "기존 프로젝트 적용"의 수동 절차를 따른다.
