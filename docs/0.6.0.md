# 0.6.0: /start-vibe 비용 개선 결과

`vibe loop`, `vibe ci wait`, `vibe brief`, `vibe format`을 추가하고 Claude·Codex 어댑터, 검증 기본값, 설치되는 공통 스킬을 함께 변경했다. 버전은 0.6.0이며 이 작업에서 npm 게시·원격 push는 수행하지 않았다.

## 설계 선택과 대안

| 항목 | 채택한 기본값 | 대안과 이유 |
|---|---|---|
| 세션 경계 | 바깥 CLI가 단위마다 새 headless 프로세스. Claude 새 UUID, Codex 새 exec, resume 금지 | 한 대화의 자동 요약·resume는 이전 입력 재독을 줄이는 경계가 아니므로 단독 반복에 쓰지 않음. 기존 work runner의 resume 동작은 유지 |
| 단위 | 태스크 1개 done, 기획 조각(SSOT+create-task), inbox 정리, 경량 수정 | SSOT 수정과 create-task를 별도 세션으로 나누면 같은 결정을 다시 읽게 되므로 한 조각에 합침 |
| 혼자 작업 | 태스크별 커밋, 기본 3태스크 또는 조각 소진·실행 끝의 묶음 push. 보고서는 push 경계에서 갱신 | 태스크마다 선점/보고서 push를 하면 문서 커밋·CI 대기가 반복됨. `--batch-size`로 조절. 단위 세션 종료는 묶음 종료가 아님 |
| 다른 세션 | 원격 active/doing/wip와 로컬 미게시 active도 보수적으로 감지. strict는 별도 선점 커밋·push·sync 뒤 원격 소유 재확인 | 단독 최적화를 동시 세션에 적용하지 않음. 같은 checkout의 loop는 잠금으로 하나만 실행 |
| 권한 | Claude acceptEdits+Read/Edit/Write/Glob/Grep 및 명시적 Bash 허용 목록, Codex workspace-write+approval never. 메인 checkout에서 실제 probe | 새 worktree는 프로젝트 허용 목록이 적용되지 않을 수 있음. 우회는 명시적인 `--permission-mode bypass`만 허용. trust 여부를 경로만 보고 단정하지 않고 실제 probe 결과를 기록 |
| CI | gh → 토큰 API → 공개 HTML. backoff 15초→최대 120초, HTML은 최소 60초. SHA 일치 검증 | 인증 없는 API(60회/시간)는 전혀 호출하지 않음. 로그/아티팩트는 인증이 필요하므로 공개 경로에서는 job/step 결론만 읽음 |
| run 없음 | 보수적으로 해석 가능한 push paths/paths-ignore는 즉시 skipped. 불명확하면 기본 2분 유예, 전체 기본 1시간 제한 | 지원하지 않는 glob/YAML은 추정해 즉시 건너뛰지 않음. 조회 오류는 skipped로 숨기지 않고 timeout으로 실패 |
| 검증 | task=영향 테스트+빠른 검사, batch=코드 push 전 전체 검사 1회, CI=push 뒤 | 단계 없는 ARCH에서 전체 verify를 태스크에 붙이지 않음. legacy 프로젝트는 package.json verify/test 또는 `--verify`로 batch 지정. batch 없는 코드 push는 차단 |
| work 호환 | ARCH task→task-verify, batch→verify(unit integration), CI가 최종 관문이면 group-verify 생략 | 추가 로컬 최종 관문이 있는 기존 그룹의 group-verify는 유지 |
| 작은 수정 | 버그/문구/스타일, 코드+테스트 3파일·추가+삭제 100줄 이하, 새 결정/SSOT 규칙/계약/저장/마이그레이션 변경 없음 | 범위를 넘거나 판단 공백이 생기면 즉시 create-task/update-ssot. STATE log는 `- YYMMDD fix <area>: <what>` |

loop는 기본 최대 100단위·8시간, 단위 timeout 1시간이다. HEAD와 STATE가 연속 2회 같음, 세션 실패 연속 2회, 남은 일 없음, parked만 남음, 개수/시간 제한, STOP 또는 종료 신호에 멈춘다. 반복기만 active와 보고서를 열고 닫으며, 각 단위는 같은 tag·보고서를 잇는다. 진행과 실패 로그는 `.git/haeram/v1/loops/<tag>/`에 보존한다. 실패한 batch는 코드 push를 막는다. CI 실패는 실제 수정 태스크 파일과 STATE next로 넘기고 현재 실행을 멈춘다.

정지 중인 검증·CI는 중단할 수 있다. 이미 실패했거나 미완료인 코드는 자동으로 push하지 않으므로 실패 종료 시 active 제거·보고서 마감 커밋이 로컬에만 남을 수 있다. 다음 실행에서 보존된 상태를 확인한다. 1시간 체크포인트는 단위 세션 수와 관계없이 호스트가 관리한다.

## 고정 입력 측정

대상 이름·도메인·태스크 ID는 익명화했다. 측정 수치와 한계는 원래 기록 그대로이며 대상 프로젝트의 원문은 포함하지 않는다.

실제 anonymized-project의 STATE·FORMAT을 같은 스냅샷으로 비교했다. 측정 원문은 저장하지 않고 [수치 JSON](context-0.6.0.json)만 남겼다. `o200k_base`와 `cl100k_base`는 비교용 tokenizer이며 Claude의 과금 토큰과 동일하지 않다.

| 입력 | 전 o200k | 후 o200k | 감소 |
|---|---:|---:|---:|
| start-vibe 본문 | 2,740 | 2,122 | 22.6% |
| implement-task 본문 | 4,128 | 1,824 | 55.8% |
| manage-work 본문 | 4,402 | 886 | 79.9% |
| STATE 전체 → status 요약 | 5,842 | 2,457 | 57.9% |
| FORMAT 전체 → task 발췌 | 6,105 | 2,076 | 66.0% |
| 태스크 세션 합계¹ | 18,815 | 8,479 | 54.9% |

¹ start-vibe+implement-task+STATE/요약+FORMAT/발췌. UTF-8 75,358→31,423 bytes(58.3% 감소), cl100k 21,796→10,053(53.9% 감소). 태스크별 브리핑·provider wrapper와 제공자가 주입하는 시스템 프롬프트는 제외했다. 숨겨진 시스템 프롬프트는 이 저장소에서 관찰할 수 없으므로 “시스템 포함 전체 비용”으로 해석하면 안 된다. 실제 세션의 누적 입력·최대 문맥·과금 측정도 아니다.

측정 명령 형식(원래 입력은 미포함): `node scripts/measure-context.mjs --target <project-path> --baseline-ref <JSON의 baselineRef>`. 토큰까지 계산하려면 임시 Python 경로에 tiktoken을 설치하고 `PYTHONPATH=<임시 경로> ... --tokens`를 추가한다. CLI에는 tokenizer 의존성을 추가하지 않았다.

## 검증 범위

`npm run check` 통과(전체 159개 테스트·validate·pack:check). 후속 관련 회귀 60개와 마지막 반복기 회귀를 추가로 확인했다.

- 가짜 command adapter: 새 프로세스/세션 3개, preflight 1회, tag/보고서 공유, 진척 없음·실패 연속 2회, 개수/시간/STOP/parked/일 없음 종료, detached 호스트, 실행 중 종료, solo/strict 묶음 경계, 검증 실패 시 push 차단, CI 실패 수정 태스크를 검증했다.
- 가짜 HTTP/git/gh: 성공·실패·실패 step, 토큰 한도 초과→HTML, 익명 API 0회, 다른 SHA의 오래된 run 배제, paths-ignore와 유예, HTTP 장애 timeout, 미완료 job의 step 결론 오인 방지를 검증했다.
- brief의 인용 블록·신선도·touches, ARCH r12 형태, FORMAT 발췌, 짧은 검사 출력과 전체 로그, 시작 SHA 보존·환경변수·캐시 범위·명령 timeout, 새 fix log와 legacy 문서 lint, 0.5→0.6 lock/reference 갱신을 검증했다.
- 기존 work run/next/submit/integrate 및 다중 clone 선점·30태스크/6워커 회귀 테스트를 함께 실행했다.
- 실제 anonymized-project: 양쪽 스킬 install/check 성공, 기존 spec lint 성공(13 SSOT, 당시 56 남은 태스크·198 완료, 의미 검토 후보 27건), loop dry-run과 T001 brief 성공. ARCH r12의 task 명령 4개·batch 명령 5개와 조건부 Chromium 지침을 확인했다.

anonymized-project에는 살아 있는 다른 세션과 STATE 변경이 있어 실제 구현 반복을 실행하지 않았다. 따라서 CSS 수정 10분/40호출, 실제 세션 최대 문맥 20만 이하는 **미측정**이다. CI 대기 중 모델 호출 0회는 프로세스 구조와 가짜 실행 테스트로 검증했으며 실제 원격 CI 비용 실측으로 보고하지 않는다. 실제 Claude 2.1.303·Codex 0.163.0에서 필요한 CLI flag는 help로 확인했다. Codex 실행·스키마·로그 방식은 [공식 비대화형 실행 문서](https://developers.openai.com/codex/noninteractive/)도 확인했다.

작업 중 별도로 추가된 `src/spec-context.mjs`와 변경된 `src/spec-format.mjs`는 보존했다. 이 보고서의 구현 범위에는 포함하지 않는다.

## 설치 프로젝트 갱신

게시 후 프로젝트에서:

```bash
npx haeram-spec-creator@0.6.0 install --dry-run
npx haeram-spec-creator@0.6.0 install
npx haeram-spec-creator@0.6.0 check
npx haeram-spec-creator@0.6.0 lint
npx haeram-spec-creator@0.6.0 vibe loop --tag k3f9 --provider claude --dry-run --json
```

게시 전 로컬 소스는 `node /path/to/haeram-spec-creator/bin/haeram-spec-creator.mjs install --target <project>`로 설치하고 같은 실행 파일로 새 CLI를 사용한다. 스킬만 복사하는 install은 CLI 실행 파일을 프로젝트에 설치하지 않으므로 이전 CLI를 npx로 실행하지 않도록 버전을 고정한다.

기존 `.haeram-spec-creator-lock.json` schemaVersion=1을 그대로 사용하고 packageVersion·파일 hash와 새 references를 갱신한다. 로컬에서 고친 설치 파일은 기존처럼 충돌을 보고하며 --force 없이 덮어쓰지 않는다. 프로젝트의 spec/STATE·FORMAT·SSOT는 설치로 덮어쓰지 않는다. 새로운 FORMAT 정본은 설치 스킬의 create-architecture/assets/FORMAT.md 및 `vibe format --section ...`에 있고 기존 프로젝트 문서는 lint 호환을 유지한다. 프로젝트의 별도 FORMAT 제약이 있으면 그 관련 섹션도 확인하고 새 경량 fix/검증 단계 표기를 해당 프로젝트 규칙에 반영한다.

실행은 README 예시처럼 `--detach`, 중지는 같은 tag의 `--stop`을 사용한다. 재개 전 STOP 표식을 지우고 실패 로그·미완료 변경을 확인한다. 단독 반복은 clean checkout에서 시작하며 다른 작업 묶음에 배정된 checkout은 work run을 사용한다.
