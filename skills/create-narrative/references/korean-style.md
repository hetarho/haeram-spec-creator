# 한국어 글쓰기 규칙집 (create-narrative 전용)

> NARRATIVE.md를 쓸 때 적용하고, 퇴고 때 체크리스트로 쓴다. 각 규칙: 원칙 + ✗나쁜 예 → ✓좋은 예.
> 출처: 토스 라이팅 원칙 · LINE Technical Writing Day · 카카오엔터프라이즈 테크니컬 라이팅 · technical-writing.dev · 국립국어원 공공언어 지침 · 이오덕 「우리 글 바로 쓰기」 · 유시민 「글쓰기 특강」 · 공개 한국어 글쓰기 스킬(DaleSeo/korean-skills, im-not-ai, k-skill).

## 구조
1. **결론·가치 먼저(두괄식).** 각 섹션 첫 문장은 "독자가 무엇을 얻는가"를 말한다. 배경·역사는 뒤로.
   ✗ "리버스 프록시 설정은 2019년에 도입되었고 많은 수정이 있었습니다…" → ✓ "리버스 프록시를 설정하면 네트워크 지연을 최소화할 수 있습니다."
2. **첫머리에 개요.** "이 문서를 읽으면 ~을 이해하고 ~을 할 수 있다"를 문서 맨 앞에 쓴다.
3. **한 섹션에 한 주제, 섹션당 핵심 메시지 하나.** 스펙을 다 아는 작성자는 전부 담고 싶어진다 — 욕심을 빼고, 상세가 필요한 독자는 spec/ 원문으로 안내한다.
4. **제목이 예고한 것만 본문에 쓴다.** 독자는 제목과 처음 3문장으로 "나를 위한 글인가"를 판단한다.
5. **독자가 아는 것 → 모르는 것 순서.** 비개발 독자에게는 도메인 개념부터, 그다음 시스템 동작.
   ✗ "이벤트 소싱 기반 CQRS 패턴을 적용하여…" → ✓ "주문이 들어오면 기록을 남기고, 그 기록으로 화면을 만듭니다. 이 방식을 이벤트 소싱이라고 부릅니다."

## 문장
6. **한 문장에 생각 하나.** "~하며, ~하고, ~해서"로 이어지면 마침표로 끊는다. 그러면 저절로 단문이 된다.
   ✗ "버튼을 클릭하면 다음 단계로 이동하게 되며, 그 이후의 작업을 진행할 수 있습니다." → ✓ "버튼을 클릭하면 다음 단계로 이동합니다. 이동 후 이어서 작업하세요."
7. **주어와 서술어를 호응시키고 가깝게.** 쓴 뒤 주어+서술어만 남겨 읽어 말이 되는지 확인한다.
   ✗ "국회의원 300명을 선출되었다" → ✓ "국회의원 300명이 선출되었다"
8. **능동형으로. 이중 피동 금지.** "~되어진다, ~돼야 합니다" → 능동 또는 단일 피동.
   ✗ "변경 사항이 적용된 후 다시 빌드되어야 합니다." → ✓ "변경 사항을 적용한 후 다시 빌드하세요."
9. **행위 주체를 명시한다.** 시스템·사용자·운영자가 섞이는 설명에서 주체 생략은 오독을 만든다.
   ✗ "파일을 업로드하면 자동으로 저장됩니다." → ✓ "사용자가 파일을 업로드하면 서버가 자동으로 저장합니다."
10. **명사 나열을 동사로 푼다.** "~처리/수행/진행/작업" 연쇄 금지.
    ✗ "인증 처리가 완료된 후 접속 설정 진행이 가능합니다." → ✓ "인증한 후 접속을 설정할 수 있습니다."
11. **수식어는 대상 바로 앞에. 겹수식은 문장을 쪼갠다.**
    ✗ "5킬로그램 정도의 금 보관함" → ✓ "금 5킬로그램 정도를 담은 보관함"
12. **나열은 문법 구조를 대등하게.**
    ✗ "신선도 유지와 부패를 방지해야 한다." → ✓ "신선도를 유지하고, 부패를 방지해야 한다."

## 어휘
13. **소리 내어 말할 수 있는 일상어로.** 문어체 한자어를 입말로.
    ✗ 득하다 / 용이한 / 착수하다 → ✓ 얻다 / 쉬운 / 시작하다
14. **잡초 단어 제거.** 빼도 뜻이 같으면 뺀다.
    ✗ "로그 파일을 삭제하는 작업을 수행합니다." → ✓ "로그 파일을 삭제합니다."
15. **모호어 대신 수치·기준.** "많을 때, 빠르게, ~일 수도" 금지 — spec에 수치가 있으면 그대로 쓴다.
    ✗ "데이터가 많으면 느려질 수 있습니다." → ✓ "데이터가 10,000건을 넘으면 응답에 1초 이상 걸립니다."
16. **전문용어는 첫 등장에서 풀어 쓰고 병기, 이후 한 표기만.**
    ✗ "Exception을 던집니다." → ✓ "예외(Exception)를 일으킵니다."
17. **같은 개념은 같은 단어로, 어조(합니다체)도 하나로.**
    ✗ "사용자는 화면을 확인합니다. 유저가 페이지 설정을 바꿔요." → ✓ "사용자는 화면을 확인합니다. 사용자가 화면 설정을 바꿉니다."

## 번역투·AI투 제거
18. **"~에 대해 / ~를 통해 / ~에 있어서" → 조사나 동사로.**
    ✗ "데이터 분석을 통해 인사이트를 얻는다." → ✓ "데이터를 분석해 인사이트를 얻는다."
19. **"가지고 있다"(have 직역) → 있다/이다/~하다.**
    ✗ "이 모듈은 강한 경쟁력을 가지고 있다." → ✓ "이 모듈은 경쟁력이 강하다."
20. **"~에 의해" 피동 → 능동.**
    ✗ "AI에 의해 생성된 이미지" → ✓ "AI가 만든 이미지"
21. **'의' 남용과 겹조사(에의/에서의/으로부터의) 제거.** 중심 명사를 동사로 풀면 우리말다워진다.
    ✗ "효과적인 읽기의 방법" / "긴장으로부터의 해방" → ✓ "효과적으로 읽는 방법" / "긴장에서 벗어남"
22. **"~할 수 있다" 연속 금지.** 단정할 수 있으면 단정한다.
    ✗ "효율을 높일 수 있다. 비용을 줄일 수 있다." → ✓ "효율을 높이고 비용을 줄인다."
23. **대명사(그/이것) 반복 → 생략하거나 명사로.** 한국어는 주어를 자연스럽게 생략한다.
    ✗ "그는 앉았다. 그는 한숨을 쉬었다." → ✓ "자리에 앉아 한숨을 쉬었다."
24. **AI 상투구 금지.** "결론적으로 / 시사하는 바가 크다 / 기계적 첫째·둘째·셋째 / 획일적 3항 나열 / 연결어미 뒤 쉼표("발전하지만, 대응은")" 금지. 문장 길이에 변화를 준다.
    ✗ "결론적으로, 이 아키텍처는 혁신적인 해결책이다." → ✓ "결국 이 아키텍처로 배포 시간이 절반으로 줄었다."
25. **메타 담화 최소화.** "아시다시피 / 앞에서 설명했지만" 같은 말은 밀도를 낮춘다 — 그냥 내용을 말한다.

## 톤
26. **강요 대신 권유 + 이유.** 지시에는 얻는 것/막는 것을 붙인다.
    ✗ "반드시 마이그레이션해야 합니다. 안 하면 심각한 문제가 생깁니다." → ✓ "마이그레이션을 먼저 실행하세요. 기존 데이터 유실을 막을 수 있습니다."
27. **독자가 막히거나 걱정할 지점에 한 문장의 공감·안내.** 과하지 않게, 문서 전체에 두어 번.
    예: "처음 보면 단계가 많아 보이지만, 실제로 손댈 파일은 두 개뿐입니다."

## 퇴고 (완성 후 반드시 두 번)
- **1차 — 내용 보존:** 수치 · 날짜 · 고유명사 · 인과관계 · 부정 표현이 spec 원문과 일치하는지 항목별로 확인한다. 다르면 고치는 쪽은 내러티브다.
- **2차 — 문장 다듬기:** 위 1~27을 체크리스트로 훑고, 소리 내어 읽듯 검토한다. 입으로 읽기 어색한 문장은 말하듯 다시 쓴다.
- **형식 배분:** 이야기는 서술식, 절차·조건은 목록, 구조는 도식 — 전부 산문으로 쓰지 않는다.
- **참조는 맥락으로 녹인다:** "AUTH-3 참조" 대신 "가입 단계에서 정한 대로 이메일은 수집하지 않습니다"처럼 어디서 나온 결정인지 문장 안에 담는다.
